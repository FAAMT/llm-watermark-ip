## IP Definition

### What the IP does

A language model writes text one token at a time. At each step it scores every
token in a vocabulary of V tokens (the logits ℓ) and **samples** the next token
with probability `softmax(ℓ)`. Normally the randomness for that draw comes from
an ordinary random number generator.

The **Gumbel watermark** replaces that randomness with randomness derived from a
secret key and the previous k tokens. It's Aaronson's scheme, also called
exponential-minimum sampling by Kuditipudi et al. For each candidate token t,
the IP hashes (key, context, t) into a number u_t in (0, 1), turns it into
Gumbel noise `G(u_t) = −ln(−ln u_t)`, and picks `argmax_t (ℓ_t + G(u_t))`.

- **The text is not distorted.** Over a random key, the chosen token has exactly
  the model's softmax distribution, which is the Gumbel-max trick. Unlike the
  green-list method, it adds no bias, so text quality is unchanged.
- **The text is still detectable.** Someone with the key recomputes u for each
  token that was actually chosen. Watermarked text chose tokens whose u was
  unusually close to 1, and a simple sum exposes this.
- **No softmax is needed in hardware.** Sampling becomes one streaming pass of
  "add noise, keep the maximum". There's no exponential, no sum over V, no
  division and no second pass.

The IP does both sides:

- **SAMPLE:** reads the context and all V logits, then returns the sampled
  token.
- **DETECT:** reads a token sequence, then returns a score S and a count N. The
  host turns them into a p-value.

The model itself (GPT-2 small, V = 50,257, or Qwen2.5-0.5B) runs in Python with
Hugging Face. Its logits are recorded and replayed by the testbench. The model
weights are never changed.

### Mathematical operations

Fixed by CONFIG:
- a 64-bit key K
- the vocabulary size V
- the context length k (1–4)
- a 64-bit nonce, used only for "free" steps

Logits are int16 Q8.8 in natural-log units. The host scales them by 1/temperature,
subtracts the maximum and clamps. For top-k sampling, the host sets excluded
logits to −32768. The hashes are the same as in Fahad's green-list plan, so
the two designs share the seed and hash hardware.

1. **Step seed**, once per generated token:
   `s = fmix64( K ⊕ ⊕_{j=1..k} ((t_{i−j} + 1) · C_j mod 2^64) )`.
   For a **free** step, where the host saw this context earlier in the same
   text: `s = fmix64( nonce ⊕ ((step + 1) · C_4 mod 2^64) )`.
2. **Keyed uniform**, for every index t in [0, V):
   `u_t = fmix32( s[31:0] ⊕ (t · 0x9E3779B1 mod 2^32) )`, read as
   `ũ_t = (u_t + 0.5) / 2^32` in (0, 1).
3. **Gumbel noise:** `G_t = −ln(−ln ũ_t)`, read from a ROM in Q8.8. Its range is
   −3.13 to 22.87.
4. **Sample:** `next = argmax_t (ℓ_t + G_t)`. On a tie, the smallest t wins.
   For a random key this has exactly the distribution `softmax(ℓ)`, apart from
   fixed-point rounding.
5. **Detect:** for each token i ≥ k that the host has not marked to skip,
   recompute u for the chosen token and add the score `−ln(1 − ũ)`, read from a
   ROM in Q5.11.
   `S = Σ score_i` (uint32, Q21.11) and `N` = the number of tokens scored.
   For unwatermarked text each score is Exp(1), so S ~ Gamma(N, 1). The host
   computes `p = gammaincc(N, S)` and declares the text watermarked if
   p < 10⁻⁶. This is the exact test from Fernandez et al., used in Meta's
   `three_bricks` code.
6. **Repeated contexts:** if the same k-token context appears twice, the same
   noise would repeat, making the text repetitive and the p-value invalid.
   Generation therefore uses a free (unkeyed) seed for a repeated context, and
   detection skips tokens whose context was already seen. The host computes the
   repeat flags with one hash set.

**The ROM addressing** ("rom_index") makes the table accurate in both tails,
where the winning tokens come from:
- Take w, the distance of u from the nearer end: `w = u` if u < 2^31,
  otherwise `2^32 − 1 − u`.
- Find e, the leading-zero count of w.
- Take m, the 8 bits after w's leading one.
- The address is `(half·33 + e)·256 + m`, giving 16,896 entries of 16 bits.

This works like a small floating-point number: a leading-zero count and a shift,
with no logarithm hardware. The error is under 1 LSB of Q8.8. A plain table on
the top 16 bits of u would clip the upper tail at u > 1 − 2^−16, which happens
for about 0.8 of the 50,257 tokens at every step. Those tokens are the likely
winners, so the clipping would bias the sampling.

### Golden model (Python, bit-exact)

The ROMs are generated by this model and included in the HLS code as a header,
so the hardware matches it bit for bit by construction.

```python
import math, numpy as np
M32, M64 = (1 << 32) - 1, (1 << 64) - 1
C_IDX = 0x9E3779B1                       # odd: t -> t*C_IDX is a bijection mod 2^32
C_CTX = (0x9E3779B97F4A7C15, 0xBF58476D1CE4E5B9, 0x94D049BB133111EB, 0x2545F4914F6CDD1D)

def fmix64(k):                           # MurmurHash3 64-bit finalizer (seed_unit)
    k ^= k >> 33; k = (k * 0xFF51AFD7ED558CCD) & M64
    k ^= k >> 33; k = (k * 0xC4CEB9FE1A85EC53) & M64
    return k ^ (k >> 33)

def fmix32(h):                           # MurmurHash3 32-bit finalizer on a uint64 array
    h = h ^ (h >> 16); h = (h * 0x85EBCA6B) & M32
    h = h ^ (h >> 13); h = (h * 0xC2B2AE35) & M32
    return h ^ (h >> 16)

def step_seed(key, ctx):                 # ctx = previous k token ids, oldest first
    x = key
    for j, t in enumerate(reversed(ctx)):
        x ^= ((t + 1) * C_CTX[j]) & M64
    return fmix64(x)

def free_seed(nonce, step):              # seed for a step whose context repeats
    return fmix64(nonce ^ (((step + 1) * C_CTX[3]) & M64))

def uniforms(seed, idx):                 # hash_lanes: one uint32 u per token index
    t = np.asarray(idx, dtype=np.uint64)
    return fmix32(((t * C_IDX) & M32) ^ np.uint64(seed & M32))

def pf_index(u):                         # rom_index: pseudo-float address of u
    u = np.asarray(u, dtype=np.uint64)
    half = u >> np.uint64(31)                                    # 1 if u >= 2^31
    w = np.where(half == 1, np.uint64(M32) - u, u)               # distance to nearer end, < 2^31
    e = (32 - np.frexp(w.astype(np.float64))[1]).astype(np.uint64)  # leading zeros (32 if w == 0)
    m = ((w << (e + np.uint64(1))) & np.uint64(M32)) >> np.uint64(24)  # 8 bits after leading one
    return (half * np.uint64(33) + e) * np.uint64(256) + m

def build_roms():                        # generated once; the C++ #includes the same tables
    G = np.zeros(2 * 33 * 256, np.int16)     # Gumbel noise, Q8.8
    S = np.zeros(2 * 33 * 256, np.uint16)    # detection score, Q5.11
    for half in (0, 1):
        for e in range(1, 33):
            for m in range(256):
                if e == 32:
                    if m: continue
                    lo = hi = 0
                elif e <= 23:
                    lo = (256 + m) << (23 - e); hi = lo + (1 << (23 - e)) - 1
                else:
                    if m & ((1 << (e - 23)) - 1): continue   # address never produced
                    lo = hi = (256 + m) >> (e - 23)
                x = ((lo + hi) / 2 + 0.5) / 2**32             # distance of u~ to nearer end
                neg_ln_u = -math.log1p(-x) if half else -math.log(x)       # -ln(u~)
                neg_ln_1mu = -math.log(x) if half else -math.log1p(-x)     # -ln(1-u~)
                a = (half * 33 + e) * 256 + m
                G[a] = round(256 * -math.log(neg_ln_u))
                S[a] = round(2048 * neg_ln_1mu)
    return G, S
G_ROM, S_ROM = build_roms()

def sample(key, ctx, logits_q88, free=False, nonce=0, step=0):    # SAMPLE command
    s = free_seed(nonce, step) if free else step_seed(key, ctx)
    v = logits_q88.astype(np.int32) + G_ROM[pf_index(uniforms(s, range(len(logits_q88))))]
    t = int(np.argmax(v))                # first maximum: smallest index wins ties
    return t, int(v[t])

def detect(key, tokens, skip, k):        # DETECT command: S in Q21.11, N tokens scored
    S = N = 0
    for i in range(k, len(tokens)):
        if skip[i]: continue
        u = uniforms(step_seed(key, tokens[i - k:i]), [tokens[i]])
        S = (S + int(S_ROM[pf_index(u)[0]])) & M32; N += 1
    return S, N

def p_value(S, N):                       # host: score ~ Gamma(N, 1) for unwatermarked text
    from scipy.special import gammaincc
    return gammaincc(N, S / 2048)

def repeat_flags(tokens, k):             # host: True where the k-token window was seen before
    seen, out = set(), []
    for i in range(len(tokens)):
        w = tuple(tokens[max(0, i - k):i])
        out.append(i >= k and w in seen); seen.add(w)
    return out
```

**Prototype check (already run):**
- Over 2,000,000 random inputs, the ROM noise has mean 0.5768 (exact 0.5772)
  and variance 1.6438 (exact 1.6449).
- Over 200,000 contexts with 5 fixed logits, the sampled frequencies match
  softmax (χ² = 1.05; the 95% cutoff is 9.49).
- On a toy model, 200-token watermarked texts gave p < 10⁻¹⁵⁰. A wrong key and
  plain sampling gave p ≥ 0.01.

### Why it suits hardware acceleration

- **Sampling without softmax.** Normal sampling needs V exponentials, a sum, a
  normalization, a running sum and a search. Gumbel-max replaces all of that
  with V additions and a maximum: one streaming pass, integer-only.
- **Highly parallel.** The V keyed hashes and table lookups don't depend on
  each other. P lanes handle P tokens per clock at II = 1. The argmax is a
  P-input reduction tree plus a running maximum.
- **On the critical path.** It runs once per generated token inside the decode
  loop, so its latency adds to every token.
- **Small, fixed state.** Only the key, one seed and the running maximum. The
  ROMs are fixed, and no memory grows with V.
- **Fast detection.** Every token's seed depends only on input tokens, so the
  detector scores several tokens per clock at II = 1. That's useful for
  scanning large amounts of text.

### How it talks to the host

This uses the course command-response pattern (Waveflow): one AXI4-Stream in
(commands and data), one AXI4-Stream out (responses), and AXI-Lite for status
only (halted, error code, tx_id). The stream width is W = 64 bits (to be
confirmed with Waveflow; see the open questions). On a PYNQ board an AMD AXI
DMA drives both streams.

| Command | Header fields | Data after the header | Response |
|---|---|---|---|
| CONFIG (0) | K, V, k, nonce | none | none |
| SAMPLE (1) | free bit, step, k context ids | ⌈V/4⌉ beats of 4 int16 logits (padded with −32768), TLAST on the last | header + one beat: token id and its winning value ℓ + G |
| DETECT (2) | T | ⌈T/2⌉ beats of 2 words: bits [23:0] token id, bit 31 skip; TLAST on the last | header + one beat: S (Q21.11) and N |
| END (3) | none | none | none; the kernel returns |

**Error codes:**

| Code | Error |
|---|---|
| 1 | Header TLAST early or missing |
| 2 | Unknown command |
| 3 | SAMPLE or DETECT before CONFIG |
| 4 | Bad parameter: V = 0 or V > 2^24, k outside 1–4, or T ≤ k |
| 5 | Data TLAST early |
| 6 | Data TLAST missing |

## IP Architecture

```
SAMPLE  in ─► controller ─► seed_unit ─s─► hash_lanes[P] ─u─► rom_index[P] ─► gumbel_rom ─G─┐
                 └─► logit_unpack ─ℓ (P per beat)──────────────────────────────────────► add_argmax ─► resp ─► out
DETECT  in ─► controller ─► ctx_shift ─► detect_lanes[P_d] (seed ► hash ► rom_index ► score_rom) ─► score_acc ─► resp ─► out
```

### Sub-modules

1. **controller:** parses Waveflow headers, checks errors in Lab 5 order, holds
   the CONFIG values and writes the AXI-Lite status.
2. **seed_unit:** fmix64 over the key and the context, or over the nonce and
   step for a free step. It runs once per SAMPLE, so it's off the critical path.
3. **hash_lanes (P copies):** lane p handles index t = cP + p. The index
   multiply becomes an accumulator that adds P·0x9E3779B1 each cycle. Each lane
   has one pipelined fmix32 (2 constant multiplies).
4. **rom_index (P copies):** a 31-bit leading-zero count and a barrel shift,
   giving the ROM address. LUTs only.
5. **gumbel_rom:** the 16,896 × 16-bit table (about 8 BRAM36). Its two ports
   serve two lanes, so there are P/2 copies.
6. **logit_unpack:** splits each 64-bit beat into 4 int16 logits and pads the
   lanes past V with −32768.
7. **add_argmax:** P additions (ℓ + G, 18-bit), a P-input max tree, and a
   running maximum with its index across beats. Ties go to the smaller index.
8. **ctx_shift + detect_lanes (P_d copies):** a shift register supplies each
   lane with its k previous tokens. Each lane runs a fully pipelined fmix64,
   an fmix32, rom_index and a score ROM (16,896 × 16-bit, Q5.11). Skipped
   tokens contribute 0.
9. **score_acc:** an adder tree over the P_d lanes plus a 32-bit accumulator
   for S and a counter for N.
10. **resp:** builds the response header and payload beat for the output
   stream.

### Interfaces

| From → To | Connection type | What it carries |
|---|---|---|
| PS → controller | AXI4-Stream in, 64-bit | command headers with tx_id, then logits or token words, ending in TLAST |
| resp → PS | AXI4-Stream out, 64-bit | response header (tx_id, nwords), then token + value, or S + N |
| controller → PS | AXI-Lite registers | halted, error code, tx_id |
| controller → seed_unit | FIFO (`hls::stream`) | K or nonce, the k context ids, step and the free bit, once per SAMPLE |
| seed_unit → hash_lanes | FIFO | 32-bit seed s[31:0] |
| hash_lanes → rom_index → gumbel_rom | FIFO, P per cycle | u (32-bit), then a 15-bit address |
| gumbel_rom → add_argmax | FIFO, P per cycle | G (int16, Q8.8) |
| controller → logit_unpack → add_argmax | FIFO | 64-bit beats, then P int16 logits per cycle |
| controller → ctx_shift → detect_lanes | FIFO | token words, then (context, token, skip) per lane |
| detect_lanes → score_acc | FIFO, P_d per cycle | score (uint16, Q5.11) |
| add_argmax, score_acc → resp | FIFO | the result words |

No shared memory is used, and the IP has no AXI master. The top level is an
HLS dataflow region with ready/valid flow control throughout.

### Efficiency plan (what we'll measure)

| Item | Estimate | Measure |
|---|---|---|
| SAMPLE, W = 64 (P = 4) | ⌈50,257/4⌉ = 12,565 cycles, about 126 µs per token at 100 MHz | co-sim latency, II |
| SAMPLE, W = 128 (P = 8), if supported | 6,283 cycles, about 63 µs | the same |
| DETECT, W = 64 (P_d = 2) | 2 tokens per clock | the same |
| Resources per sampling lane | about 6 DSP (fmix32) + half a gumbel_rom (about 4 BRAM36) | synthesis |
| ROM precision M (mantissa bits) | M = 6, 7, 8 trade BRAM against accuracy | BRAM count and χ² test for each M |
| Software baseline | NumPy Gumbel sampling and detection on the Mac | time per step |

SAMPLE is limited by **input bandwidth**, not by compute: every logit must
cross the stream once, so P is set to W/16. Making the stream wider (more DMA
channels) is the scaling knob. If the IP sat next to an on-chip LM head, the
logits wouldn't cross a bus and P could grow further. We'll state this in the
results.

## Verification plan

1. **Unit tests:** each sub-module's C testbench against its Python function:
   - seed_unit ↔ `step_seed` / `free_seed`
   - hash_lanes ↔ `uniforms`
   - rom_index ↔ `pf_index`
   - add_argmax ↔ `sample`
   - detect path ↔ `detect`

   Edge cases: u = 0, 1, 2^31 − 1, 2^31 and 2^32 − 1, and ties in the argmax.
2. **Bit-exact:** C simulation and co-simulation compared with the model.
   Co-sim uses V = 1,024 and a few steps; full V runs in C simulation.
3. **Distortion-free check (statistical):** sample frequencies against softmax
   with a χ² test, as in the prototype check, for each ROM precision M.
4. **Detector calibration:** p-values on unwatermarked GPT-2 text should be
   uniform (Kolmogorov-Smirnov test), and false-positive rates at 10⁻³ should
   match.
5. **Detection power:** tokens needed to reach p < 10⁻⁶ at temperatures 0.7
   and 1.0, and for k = 1, 2, 4. Also the fraction of free steps for each k.
6. **Error handling:** every error code in its own activation, then a fresh
   activation that passes.
7. **Automation:** one script builds the ROMs, runs the model, C simulation,
   co-simulation and synthesis, and compares everything.

## Alternatives considered

| Decision | Alternative A | Alternative B | Alternative C | Chosen |
|---|---|---|---|---|
| Computing G(u) | Plain table on the top 16 bits of u: clips the tail and biases sampling | **Floating-point-style ROM** (leading-zero count + 8 mantissa bits) | Two hardware logarithm units per lane (CORDIC): more DSPs and latency | **B** |
| Watermark | Green list (Kirchenbauer): adds bias δ, distorts the text | **Gumbel (Aaronson)**: distortion-free sampling | Inverse-transform with a key sequence (Kuditipudi): robust to edits, but detection is an alignment search over shifts | **B** (C as a stretch goal) |
| Repeated contexts | Ignore them: repetitive text and an invalid p-value | **Free seed on repeat + skip in detection** | Remove repeats in hardware with a hash set | **B** (C as a stretch goal) |
| Context state | IP remembers the generated tokens | **Host sends k context ids in each SAMPLE** (stateless) | none | **B**: simpler to test |
| Detection test | z-score approximation | **Exact Gamma p-value** (Fernandez et al.) | none | **B** |

## Gumbel vs green list (for the team decision)

| | Green list (Fahad's plan) | Gumbel (this plan) |
|---|---|---|
| Text quality | Slightly changed by the δ bias | **Unchanged** (distortion-free) |
| Detection strength (MarkMyWords benchmark) | **Best overall**, including at low temperature | Close at temperature 1, weaker at low temperature |
| Randomness | Needs a separate random number generator for sampling. Our BIAS + argmax is greedy, not true sampling. | **True sampling on chip** with no softmax |
| Same prompt, same key | Varies, if sampled | **Always the same text**: a known limitation |
| Hardware bottleneck | MASK mode is compute-bound, so P can grow to 32 | Bandwidth-bound: P = W/16 |
| Extra hardware | A comparator per lane | A ROM per 2 lanes (about 8 BRAM36) and an argmax tree |
| Risk | Low | Low to medium: the ROM design is new, but the prototype passes |

**Options:**
- **A. Green list only:** Fahad's plan as it stands.
- **B. Gumbel only:** this plan.
- **C. Hybrid (recommended):** one IP with a MODE field. Both modes share the
  seed_unit, hash_lanes and the argmax tree.
  - **GUMBEL mode:** keyed noise, as in this plan.
  - **GREEN mode:** adds δ to the green tokens (one comparator on the same u),
    then samples with unkeyed Gumbel noise from the free seed. This is the
    paper's green-list sampling, done properly on chip.
  - The detector computes both the green count and S from the same u.
  - It costs about one extra week and gives the strongest results: quality
    against detection strength for both methods on the same hardware.
